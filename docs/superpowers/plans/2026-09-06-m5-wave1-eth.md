## Design Decisions

1. The cycle reducer generalizes once, output-compatibly. A new
   `run_crypto_research_cycle(team_id, ...)` in
   `crypto_research_cycle.py` parameterizes the team, its item set, and
   its evidence adapter over the existing BTC logic; the public
   `run_btc_research_cycle` remains as a thin wrapper. The identity hash
   payload becomes
   `CYCLE_VERSION|team_id|condition_id|bundle_id|config_version|base_probability`;
   BTC cycle_id strings therefore change format once (documented here)
   while forecast, evidence, and operator-packet outputs stay identical
   for identical inputs. Acceptance criterion 2 is interpreted
   accordingly: outputs byte-stable, identity deterministic per input.
2. ETH evidence mirrors BTC honesty: `eth_spot_price` from a registered
   `kraken_eth_ticker` source (`pair=ETHUSD`, same host, family
   `kraken_public` — one provider family per item by design, corroboration
   requires a second family later), zero probability impact, blocked
   items as zero-weight reason-coded inputs.
3. One new CLI command: `crypto-research-cycle --team {crypto_btc,
   crypto_eth} --market <slug-or-0x>` reuses the extracted, generalized
   handler; `btc-research-cycle` stays unchanged. The inventory grows
   78 -> 79 as an explicit, documented compatibility decision.
4. Unsupported is explicit, never silent: the domain matrix records per
   team the source-availability verdict; dispatch already refuses
   undefined item sets (`team_item_requirements_not_defined`), and the
   matrix documents that refusal as the intended state for teams without
   registered evidence sources.
5. Macro rates stays unsupported this wave: no viable unauthenticated
   public rates source is registered; the matrix records the criterion
   for accepting one later (public HTTPS GET, no key, documented update
   cadence, persistence-policy compatibility).
